fl-doctor — briefing

The problem

When an Illumio FlowLink user says "I configured the switch to export flows to FlowLink, but I don't see the servers on the map", finding the break takes hours: tcpdump and tshark on the collector, reading FlowLink logs, and several rounds of questions. The break can be at any of five links: exporter, collector host, FlowLink, delivery to the PCE, or the PCE.

Four failures seen in the field (anonymized):

  1. FlowLink never uploaded anything. The collector could not resolve DNS for the PCE. The error was in the log on every attempt.
  2. Millions of "bad data" drops. They were 100% ICMP, not a data problem.
  3. Wrong capture point. The exporter did not see the server segment, so the IPs the Illumio FlowLink user was looking for never appeared.
  4. Wrong port. The exporter sent to a UDP port FlowLink was not listening on.

What fl-doctor is

A terminal tool (TUI and CLI) in one static Linux binary, run on the FlowLink collector. It answers in minutes: are flows arriving, from which switch, does a given IP appear, does FlowLink process and deliver it, and what evidence goes to support.

The five use cases that matter

Illumio FlowLink user's questionWhat fl-doctor shows
"Where does the chain break?"Home: links A–E (exporters, host, FlowLink, delivery, PCE) and a funnel: wire → socket → decoded → delivered (fig. 1)
"Is my switch sending, and to the right port?"Exporters: version, port, templates, sampling, and whether FlowLink accepts each one (fig. 2)
"Do I see this server's flows, and how far do they get?"An evidence ladder N0–N4 for any IP: seen on the wire, accepted by FlowLink, processed, delivered with HTTP 204 (fig. 3)
"Why do I never see uploads?"FlowLink › Log: cycles, 204 responses, DNS and connection errors to the PCE, drops with the dominant protocol (fig. 4)
"What do I send to support?"One key builds a bundle: summary in Spanish and English, relevant log, configuration with secrets hidden, and the pcap (fig. 5)

The figures come from a lab collector with live traffic and synthetic data: documentation address ranges and invented names, no real site.

Guarantees

  • Read-only. It changes nothing in FlowLink, the firewall, routes or sysctl. It does not open the collector's ports and does not take packets away from FlowLink (it copies traffic like tcpdump).
  • Light. Fixed memory budget: measured about 22 MB with the normal profile (a brief startup peak of up to about 33 MB, inside its 64 MB budget) and about 14 MB with lean (32 MB), flat over a 5-minute replay of a real NetStream capture on a Rocky 9 x86_64 VM. Low CPU priority.
  • No dependencies. One static binary; tcpdump or tshark are optional. selftest checks the platform before you start.
  • Evidence ready for support. Secrets hidden, the pcap in original or trimmed form, and the exact command to copy the bundle to the operator's home folder. Nothing leaves the machine on its own. An IPFIX file of 199,569 records decodes the same as tshark.

Status

Version 0.1.0: static binaries for Linux x86_64 and aarch64, with SHA256SUMS and SBOM (not signed). Tested on Rocky 9, UBI 8 and in a VM; not yet validated on a real Illumio FlowLink user's collector, and RHEL 7 is not verified.

Important: fl-doctor is an unofficial field tool: it is not an Illumio product, it is not supported by Illumio, and it is provided "as is".

Next steps

  • Download the binary and the documentation from the public fl-doctor repository. Run selftest first, then sudo fl-doctor on the collector.
  • For a POC with FlowLink: first run on a lab or pilot collector; if anything fails, the evidence bundle goes to support.
  • Feedback wanted from the field: collectors where it breaks, FlowLink versions beyond 2.0.0, and exporters from other vendors. Contact: Eric Roscher.
